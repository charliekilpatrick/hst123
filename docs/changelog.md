# Changelog

Notable changes to hst123. Version numbering follows semantic versioning for full releases.

## Pre-releases (historical)

- **v1.00** (2019-02-07) — Base: download, tweakreg, drizzle, dolphot parameters.
- **v1.01** (2019-02-15) — Run dolphot and scrape dolphot output.
- **v1.02** (2019-02-22) — Fake star injection.
- **v1.03** (2019-06-02) — Drizzle-all options and option/syntax cleanup.
- **v1.04** (2020-02-10) — Python 3.7.
- **v1.05** (2020-03-04) — Sanitizing reference images for tweakreg/dolphot.
- **v1.06** (2020-03-07) — Archiving (`--archive`) for large-volume analysis.
- **v1.07** (2020-03-08) — Archiving updates; `construct_hst_archive.py` helper.

## Documentation (Sphinx)

- Expanded sources: `installation.rst` (Python 3.12, Conda, DrizzlePac, DOLPHOT helper), `user_guide.rst` (work-directory layout, CLI overview, redo flags, output formats), `api.rst` (CLI entry point, full `hst123` pipeline class, `options`, `paths`, `stdio`, `workdir_cleanup`, `dolphot_catalog_hdf5`, `datamodels`, `BasePrimitive`).

## Releases

- **Unreleased** — **Scrape photometry:** DOLPHOT column lookup now matches on the image **basename** (obstable often stores absolute ``*.chipN.fits`` paths while ``*.columns`` only lists basenames); absolute paths previously made ``find_column_index_0based`` miss Measured counts / Magnitude uncertainty and wrote ``nan`` magnitudes to ``.phot`` despite a bright detection. **Gaia absolute anchor:** ``gaia_simple`` defaults to epoch-corrected Gaia (PM ± parallax), RUWE/AEN/G-mag quality cuts, Gaussian HST centroids (tight fine aperture, isolation + S/N cuts, S/N² weights; COM for the coarse pass), and a small preferred calibrator set (top ≤5 by S/N on the fine pass). If fewer than 3 good matches remain, it widens quality cuts / apertures once as a sparse-field fallback. Prefetch caches are ``v2`` and include ``parallax``, ``ruwe``, and ``astrometric_excess_noise``. **AstroDrizzle / ``--skip-tweakreg``:** with TweakReg skipped, ``run_astrodrizzle`` no longer forces ``wcskey=TWEAK`` or stamps ``WCSNAME=TWEAK`` on scratch FLCs (``astrodrizzle_wcskey_for_run``); that combination made DrizzlePac ``restoreWCS`` abort with ``MemoryError: NAXES was not set (or bad) for LOOKUP distortion…`` on FLCs whose LOOKUP distortion metadata was incomplete (issue #20). ``astrodrizzle_exc_is_restore_wcs_distortion_failure`` also recognizes failed ``D2IMARR`` / partial-restore ``CD1_2`` ``KeyError``s so the existing wcskey-unset / sanitize retries still fire. **Python:** **3.12** only (``requires-python`` ``>=3.12,<3.13``; NumPy 1.x / Astropy 5.x / DrizzlePac stack). **Documentation:** Sphinx uses **MyST** (Markdown) + reStructuredText, **sphinx_rtd_theme**, custom CSS/layout (Swift_host_subtraction-style), intersphinx (Python/NumPy/Astropy), and GitHub Pages via CI; README badges for build, docs workflow, and site. `hst123.utils.dolphot_catalog_hdf5`: parse DOLPHOT ``*.columns`` / ``*.param`` / ``*.info`` / ``*.data`` / ``*.warnings`` and write **HDF5** (`pip install h5py` or `pip install .[hdf5]`) with the full numeric catalog plus descriptive column names and JSON metadata (merged per ``imgNNNN`` when possible). ``get_dolphot_column`` uses ``parse_column_index_and_description`` for robust column index parsing. `install_psfs` ends with `relocate_all_legacy_psf_into_canonical_layout`: merges legacy `dolphot2.0/...` **`*.psf`** into the canonical tree for **ACS**, **WFC3** (`wfc3/data`, `wfc3/IR`, `wfc3/UVIS`), and **WFPC2** (`wfpc2/data`), including **sibling** `dolphot2.0/` next to `dolphot3.1/` (common conda layout). `relocate_acs_psf_into_canonical_layout` remains for ACS-only use. `hst123-install-dolphot` applies `apply_dolphot_source_patches` before `make`: patches upstream `dolphot.c` (`main` stack buffer 82→4096 bytes) to avoid macOS `sprintf` overflow / SIGTRAP on long absolute output paths; `--no-source-patches` opts out. It also applies `apply_dolphot_nan_eval_patch`: the upstream `eval()` photometry figure-of-merit ends in an **unguarded** `assert(!isnan(M));` that aborts the whole run with **SIGABRT** (`Uncaught m=nan` / `Assertion failed: (!isnan(M)), function eval, file dolphot.c, line 1712`) on multi-instrument stacks where one image yields a negative effective noise (so the per-pixel chi becomes `sqrt(negative)`); the patch mirrors `eval1()`'s non-`NAN_CRASH` handling (zero the aggregate outputs and return 0, skipping the offending star) so the run continues. `run_dolphot` additionally calls `sanitize_dolphot_param_file` (in `hst123.utils.dolphot_sky`) just before launching DOLPHOT: any `imgNNNN_file` whose science array has NaN/Inf (commonly the drizzled reference with large NaN borders) is rewritten to a single-HDU, NaN-free `*.hst123dpsan.fits` sidecar so DOLPHOT's aperture correction / magnitude evaluation stay finite. **TweakReg `fitgeometry` is now configurable** (`settings.tweakreg_defaults["fitgeometry"]`, `settings.tweakreg_fitgeometry_choices`, new `--tweakreg-fitgeometry` CLI flag, resolved by `AstrometryPrimitive._resolve_tweakreg_fitgeometry`) and defaults to **`rscale`** (shift + rotation + scale) instead of the previous hard-coded translation-only `shift`; `shift` could not remove the relative rotation/scale between multi-epoch, multi-instrument frames (different roll angles and guide-star solutions), leaving large frame-to-frame offsets in `drizzle/`. `configure_dolphot_makefile` now also comments out the upstream `export CFLAGS+= -DNAN_PRINT` (via `disable_nan_print_in_makefile_text`): that flag makes DOLPHOT print `Uncaught m=nan` for every NaN figure-of-merit it skips, which on heterogeneous / poorly-aligned multi-instrument stacks floods the log with tens of thousands of lines and slows the run; the graceful NaN handling (the `eval()` guard + `eval1()`) is unchanged, so measurements are still skipped safely — just silently. **DOLPHOT frame alignment now trusts the Gaia/TweakReg WCS by default** (`settings.global_defaults["dolphot"]` `UseWCS` 1→**2**, `Align` 2→**0**): because hst123 already ties every exposure's WCS to Gaia before DOLPHOT, the WCS is adopted as the full frame-to-reference transform instead of re-deriving it from matched stars. The previous star-matching path (`UseWCS=1`/`Align=2`) diverged on sparse or heterogeneous stacks (few common stars per frame), scrambling source positions — bright reference stars and real targets landed nowhere near their catalog detections — and dropping genuine detections; e.g. a clear 7.6σ WFC3/UVIS F625W source was absent from the catalog (0% of bright stars matched their detections), while `UseWCS=2` recovered it as a clean type-1 detection (sub-pixel WCS residuals, ~67% of bright stars matched). This makes a single all-epoch / multi-instrument DOLPHOT run (e.g. `examples/run_coords_pipeline.sh`) astrometrically correct without per-epoch splitting. New `--dolphot-use-wcs {0,1,2}` and `--dolphot-align {0..4}` CLI flags override the defaults per run (wired in `handle_args`). `tests/test_dolphot_c_python_parity.py` documents C vs Python parity for calcsky, splitgroups, acsmask, wfc3mask, wfpc2mask (optional binaries + DOLPHOT tree; marker `dolphot_parity`). `hst123.utils.progress_log.LoggedProgress`: throttled `logger.info` progress lines (`#---` bar, %, counts, elapsed, est. total duration, remaining) for reuse; wired to calcsky stage 1 in `write_sky_fits_fallback` / `compute_sky_map_dolphot` (Python per-row updates; **Numba: one full parallel pass** then a single progress completion—no sequential batched kernels that ruined throughput). Disable with `HST123_CALCSKY_PROGRESS=0` or `HST123_PROGRESS_LOG=0`. Optional **`pip install .[perf]`** adds `numba`; `environment.yml` includes `numba` for conda users. `*drc.noise.fits` (sky copy for drizzled stacks) removed in `run_dolphot` and `get_dolphot_photometry` primitive cleanup with `respect_keep_artifacts=False` so they are still removed when `--keep-drizzle-artifacts` is set (not in per-filter astrodrizzle cleanup, which would delete prior filters’ noise). Same glob listed in `settings.pipeline_products` for scripted cleanup; see `tests/test_pipeline_cleanup_validation.py`. Removed legacy CLI `--make-clean`, `--no-large-reduction`, `--large-num` and `hst123.make_clean` / `check_large_reduction`. CI: workflow uses `pip install -e ".[test]"`; `_psf_already_satisfied` treats ACS WFC PAM as present if either `make_root` or `source_dir` has a valid `acs/data` payload; scrape-dolphot unit tests supply minimal `pipeline.options`. Pure-Python DOLPHOT `splitgroups` (`hst123.utils.dolphot_splitgroups`); `HST123_DOLPHOT_SPLITGROUPS_EXTERNAL=1` forces the C binary. `DOLPHOT_REQUIRED_SCRIPTS` no longer lists `splitgroups`. DOLPHOT installer: `ACS_WFC_PAM.tar.gz` extracts under `dolphot2.0/acs/data/`; files are now copied to `acs/data/` and `dolphot_acs_data_dir` prefers directories that contain both PAM FITS. Python `calcsky` port: vectorized second pass (summed-area table); Numba first pass uses precomputed annulus offsets and a per-row scratch buffer (no per-pixel `calloc`).

- **v1.1.0** (2025-03-02) — Post–v1.07: refactored pipeline (utils, primitives), setuptools-scm versioning, tests and docs updates.
